# 写博客指南

> 用户说"把最近处理的某个事件/技术写成博客"时，按本指南执行。
> 目标：以用户视角写出真实、专业、不像 AI 生成的博客。

## 写作前：回顾与提炼

1. **回顾最近对话**：找出用户想写的事件/技术点，还原完整过程（起因 → 排查 → 方案 → 结果）。
2. **以用户视角梳理**：整篇用第一人称"我"，是"用户经历了这件事"，不是"AI 帮你做的"。全程不要出现"你/AI 让我……"这种 AI 视角。
3. **还原真实起因**：起因必须真实。例如本次是"用户先质疑是否主流"引发，不是 AI 主动要改。写清"为什么开始做这件事"。

## 内容规范

- **不捏造、不虚构**：只写实际发生的过程、实际的技术名词、实际的结果。不要脑补心理活动、对话、场景。
- **技术细节准确**：组件名、参数名、版本、报错信息、最终效果，都要和真实一致。
- **附真实链接**：过程中如果引用了文档/链接（用户发过、或查到的），以 markdown 链接形式附上，保留真实 URL。
- **过程要完整**：起因 → 查证 → 对比/尝试 → 遇到问题 → 解决 → 结论，串成一条线。别只写结论，要有过程感。

## 语气

- **专业但不生硬**：像程序员记录一次真实的技术折腾，有判断、有取舍。
- **避免 AI 腔**：不要"总而言之""综上所述""首先其次最后"这类模板；不要夸大、不要卖惨；不要明显的排比堆砌。
- **适度口语**：可以有"我当时的想法是""结果发现"这类自然表达，但别过度口语化（不要"咱""贼""666"等）。
- **不要有"教训总结"式的升华**：可以有简短收尾，但别硬凑"人生感悟"。

## 格式（沿用 content/ 现有 frontmatter）

```yaml
---
title: 文章标题
date: YYYY-MM-DD
description: 一句话摘要
url: https://new-king.com/blog/xxx
draft: true   # 可选；true 时暂不展示（列表/详情/导航/Agent 均不可见）
---
```

- 文件名：`content/posts/pN-短横线-slug.md`（N 为下一序号，看现有最大）
- 正文用 `##` 分节，markdown 规范

## 写完后

1. 让用户审阅内容（标题、语气、是否有 AI 味、是否有遗漏链接/细节）。
2. 用户确认后：
   - 提交 git
   - 同步 content 到服务器（rsync 到 `/opt/server/newking/content`）
   - 触发线上索引（`curl -X POST https://new-king.com/api/index/index`）
   - 这样 Agent 能检索到新文章。
