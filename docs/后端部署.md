# 后端部署指南（1Panel + Docker）

在 1Panel 里用 Docker 部署 Python 后端，并通过反向代理把 `/api` 转发到后端容器。

## 前置

- 服务器：111.231.13.51（1Panel 已装）
- Postgres 已在 1Panel 运行（`1Panel-postgresql-QWGQ`，映射 127.0.0.1:5432）
- 项目文件：`backend/`（含 Dockerfile、docker-compose.yml）

## 一、准备服务器目录

SSH 登录服务器，创建 content 挂载目录（后端容器读它）：

```bash
mkdir -p /opt/newking/content
```

## 二、构建并启动后端容器（两种方式二选一）

### 方式 A：1Panel 界面（推荐你熟悉 1Panel）
1. 1Panel → **容器** → **编排** → **新建**
2. 把 `backend/docker-compose.yml` 的内容粘贴进去
3. 编辑里面对应的 key 环境变量（SiliconFlow/DeepSeek/LangSmith）
4. 保存 → 部署

> 注意：编排里 `build: context: .` 需要能访问到 Dockerfile。若 1Panel 编排不方便 build，
> 建议改用"方式 B"（SSH 在服务器上 build）。

### 方式 B：SSH 命令行（更直接）
先把后端代码传到服务器：
```bash
# 在本机
scp -r backend root@111.231.13.51:/opt/newking/backend
```
在服务器上：
```bash
cd /opt/newking/backend
# 创建 .env（key 配置，不进仓库）
cat > .env << 'EOF'
SILICONFLOW_API_KEY=你的key
DEEPSEEK_API_KEY=你的key
LANGSMITH_API_KEY=你的key
LANGSMITH_ENDPOINT=https://eu.api.smith.langchain.com
LANGSMITH_PROJECT=newking-agent
EOF
# 启动（compose 里 environment 引用这些变量）
set -a; source .env; set +a
docker compose up -d --build
```

## 三、验证后端容器

```bash
docker ps | grep newking-agent
# 健康检查
curl http://127.0.0.1:8000/health
# 内容 API
curl http://127.0.0.1:8000/api/content
```

看到 `{"status":"ok"}` 和内容 JSON 即成功。

## 四、1Panel 反向代理 /api → 后端

1. 1Panel → **网站** → **new-king.com** → **反向代理**
2. 添加一条：
   - 路径：`/api`
   - 转发：`http://127.0.0.1:8000`
3. 保存并重载 Nginx

验证：浏览器访问 `https://new-king.com/api/content` 应返回内容 JSON。

## 五、知识库索引（首次 + 内容更新后）

后端读取服务器 `/opt/newking/content` 里的 md。首次 / 内容更新后触发索引：

```bash
curl -X POST http://127.0.0.1:8000/api/index/index
```

> 自动化（CI push 后自动同步 content + 触发索引）见 `docs/部署指南.md` 的 CI 扩展部分。

## 常见问题

- 后端连不上数据库：检查 compose 里 `DATABASE_URL` 的 host（`host.docker.internal`）+ 1Panel Postgres 的用户/密码/库名
- `extension "vector" is not available`：pgvector 未装（服务器 Postgres 需手动装插件，见此前 Step 2）
- 反向代理 502：后端容器没起 / 端口不对
