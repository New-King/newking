# 前端开发规则

> 改前端代码（`src/`）时，先读本文件，设计规范见 `docs/设计规范.md`。

## UI 风格（硬性要求）
- 全站必须遵循 **`docs/设计规范.md`** 的「深灰极简 · Apple 质感」设计系统。
- 颜色 / 阴影 / 圆角一律使用其中定义的令牌（`tailwind.config.js` 是令牌唯一来源，值为 CSS 变量），**禁止自行新造色值，禁止引入彩色强调（蓝 / 紫 / 绿等）**。
- **深色模式（html.dark）**：新增组件必须同时提供 `dark:` 变体；禁止使用不跟随主题的硬编码中性色（`bg-neutral-*`、`text-neutral-*`、`border-black/*`、`bg-white`），确需使用必须配 `dark:` 变体。详见 `docs/设计规范.md` §4.1。
- 新增页面 / 组件时先读 `docs/设计规范.md` 的组件规范，照已有组件样式实现。

## 布局（2026-11 改版）
- **桌面**：左侧固定目录 264px（主区 `lg:pl-[264px]`）；列表/概览用 `max-w-4xl`，文章详情正文限制 `max-w-2xl` 但左边缘与 4xl 栏对齐（不居中缩进）。
- **移动**：顶部 56px 细栏 + 左侧抽屉；主区 `pt-14`；抽屉打开时锁 `body` 滚动，点击遮罩/条目关闭。
- **AI 对话**：全局右下角浮层 `ChatDock`，由 `ChatDockProvider` 控制开关；页面里的 AI 入口用 `useChatDock().openChat(预设问题)`，不要再新增整页对话入口。
- 目录、标题搜索、主题切换都在 `Sidebar`；主题 localStorage key 仍为 `theme`。
- **版本历史**：`/history` 下 `Sidebar` 切换为 `VersionNav`（版本 → 页面），主区是 `HistoryPage` 截图；历史模式隐藏 ChatDock；截图与清单在 `public/versions/`，不要改成加载旧版构建的 iframe。

## 文案（硬性要求）
- 用户可见文案（占位符、按钮文字、页面内容、导航、错误提示等）**一律不得擅自增删改**。
- 确需改动文案时，先向用户说明并征得同意后再改。

## 开发注意（前端易错点）
- 修改 `tailwind.config.js` 后，**Vite dev server 不会热载入新配置**，需要手动重启（否则出现 CSS 500 / 类不存在的报错）。
- 设计令牌集中管理，勿在组件里写死十六进制色值。
- 按 phase/步骤显示的内容必须条件渲染，禁止用 opacity-0 占位（隐藏元素占位会导致容器内容恒超高、滚动跟随把顶部内容滚出视口）。
- 浏览器验证以截图 + 像素分析为准：`get_visible_dom` / `domSnapshot` 对 opacity 不敏感（隐藏元素也报可见），只能用于确认 DOM 存在，不能判断"是否显示"。
