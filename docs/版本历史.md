# 版本历史

`/history` 是站点的「静态截图归档」：左侧目录切换为版本列表，右侧展示对应版本、页面、设备（桌面 / 手机）的截图。

入口：左侧目录顶部品牌行右侧的历史图标。

## 目录结构

```
public/versions/
├── manifest.json
├── 2026-11-sidebar/
│   ├── home-desktop.png
│   ├── home-mobile.png
│   └── ...
└── 2025-08-chat-entry/
    ├── home-desktop.png
    ├── home-mobile.jpg
    └── ...
```

截图跟 `dist` 一起部署，纯静态，不需要后端接口。

## manifest.json

```json
{
  "versions": [
    {
      "id": "2026-11-sidebar",
      "label": "2026.11",
      "date": "2026-11-06",
      "title": "左侧目录 + AI 浮层",
      "summary": "内容优先改版：左侧目录、概览首页、右下角 AI 浮层。",
      "commit": "fb7c5a1",
      "pages": [
        {
          "id": "home",
          "label": "首页",
          "path": "/",
          "screenshots": {
            "desktop": "/versions/2026-11-sidebar/home-desktop.png",
            "mobile": "/versions/2026-11-sidebar/home-mobile.png"
          }
        }
      ]
    }
  ]
}
```

规则：

- `versions` 按日期倒序；**第一条就是「当前」**，侧栏和页面会自动标「当前」。
- 每个 `page` 的 `screenshots` 可以只有 `desktop` 或只有 `mobile`；缺的一侧，设备按钮会禁用并显示提示。
- `path` 只用于截图窗口里的地址展示，不会去请求旧页面。
- `commit` 可选；有值时展示 GitHub commit 链接。
- 页面 `id` 跨版本保持一致（如 `home`、`blog`、`projects`），方便对比。

## 新增一个版本

1. **截图**：桌面 `1440×900`、手机 `390×844`；用干净浏览器上下文，避免把 localStorage 的聊天记录/主题状态带进去；等字体和网络加载完再截，动画最好禁用。
2. **放文件**：`public/versions/<version-id>/<page-id>-desktop.png`、`<page-id>-mobile.png`。
3. **加 manifest**：在 `versions` 数组最前面加一条，`pages` 按你希望的顺序排列。
4. **本地预览**：`npm run dev` → 打开 `/history`，检查桌面/手机、每个页面、缺图提示。
5. **提交**：图片和 manifest 一起 commit；push 后随 `dist` 部署。

旧版本可以用 git worktree 抓：

```bash
git worktree add /tmp/newking-old <旧提交>
# 用旧代码起一个 dev server，截完图后
git worktree remove /tmp/newking-old
```

## 注意

- 这里是**静态截图**，不是可交互的旧构建；交互和动效以当前站点为准。
- 截图点击打开浮层大图：左右箭头 / ← → 切换页面，桌面/手机切换，X / Esc / 点空白关闭；大图按视口 fit，不再按原图尺寸撑满。
- 不要用视频替代页面归档；视频只适合做「版本演示」，当前没有启用。
- 图片按版本 id 冻结；替换同一路径的截图可能被浏览器缓存，新增版本建议用新目录。
- `manifest.json` 用 `cache: 'no-cache'` 拉取，新增版本刷新即可看到。
- 版本多、图片大时再考虑对象存储/CDN；目前直接放 `public/versions` 即可。
